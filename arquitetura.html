Arquitetura de Persistência e Controle de Acesso (OLTP)

Modelo relacional transacional que sustenta a identificação de tenant, a federação de identidade (IDP Subject) e o controle de acesso multicanal (perfis e escopos) do ecossistema multi-tenant Portais de Parceiros.

1. Camadas da aplicação

A arquitetura do microsserviço é dividida em três camadas principais para garantir desacoplamento, segurança e facilidade de manutenção.

Persistência (Banco de Dados)

Mantém a integridade transacional de entidades unificadas (pessoa, usuario), credenciais de IDP (pessoa_idp), controle de acesso por canal/perfil (canal, perfil, usuario_perfil_acesso), vínculos hierárquicos (pessoa_relacionamento) e o ecossistema multi-tenant (tenant e produto_contratados).

Regras de Negócio e Serviços (API)

Processa a resolução de tenant, faz a ponte com o Provedor de Identidade (IDP) através do IDP Subject (sub), valida status de bloqueio e resolve os perfis/escopos do usuário por canal.

Exposição / Gateway (Axway)

Ponto de entrada que valida tokens JWT, intercepta chamadas públicas de tenant e orquestra o Token Exchange para as APIs protegidas.

2. Esquema do banco de dados (DDL)

O DDL abaixo define o modelo relacional transacional atualizado, incluindo pessoa, credenciais de IDP, usuários, canais, perfis/escopos, atribuições de acesso, relacionamentos, produtos, tenants e produtos contratados. O bloco inicial de DROP ... CASCADE garante a recriação limpa na ordem correta. 

-- ==========================================
-- 0. DROP CASCADE DAS TABELAS (Limpeza inicial na ordem correta)
-- ==========================================
DROP TABLE IF EXISTS produto_contratados CASCADE;
DROP TABLE IF EXISTS tenant CASCADE;
DROP TABLE IF EXISTS produto CASCADE;
DROP TABLE IF EXISTS pessoa_relacionamento CASCADE;
DROP TABLE IF EXISTS usuario_perfil_acesso CASCADE;
DROP TABLE IF EXISTS perfil CASCADE;
DROP TABLE IF EXISTS canal CASCADE;
DROP TABLE IF EXISTS usuario CASCADE;
DROP TABLE IF EXISTS pessoa_idp CASCADE;
DROP TABLE IF EXISTS pessoa CASCADE;

-- ==========================================
-- 1. EXTENSÕES
-- ==========================================
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE EXTENSION IF NOT EXISTS "pgcrypto";

-- ==========================================
-- 2. PESSOA (Unifica Parceiro, Cliente e Operador em uma única entidade)
-- ==========================================
CREATE TABLE pessoa (
    id UUID NOT NULL DEFAULT gen_random_uuid(),
    nome VARCHAR(80) NULL,
    ativo BOOLEAN DEFAULT TRUE,
    cnpj VARCHAR(14) NULL,
    CONSTRAINT "PK_pessoa" PRIMARY KEY (id)
);

-- ==========================================
-- 3. CREDENCIAIS IDP (Exclusivo na Pessoa - Ex: Parceiro)
-- ==========================================
CREATE TABLE pessoa_idp (
    id UUID NOT NULL DEFAULT gen_random_uuid(),
    id_pessoa UUID NOT NULL,                            -- Vinculado diretamente à pessoa
    idp_subject_id VARCHAR(255) NOT NULL UNIQUE,        -- Identificador único no IDP (claim 'sub')
    provedor VARCHAR(50) DEFAULT 'COGNITO',            -- Opcional: para identificar o provedor
    criado_em TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    atualizado_em TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,

    CONSTRAINT "PK_pessoa_idp" PRIMARY KEY (id),
    CONSTRAINT "FK_pessoa_idp_pessoa" FOREIGN KEY (id_pessoa) REFERENCES pessoa (id) ON DELETE CASCADE,
    CONSTRAINT "UQ_pessoa_idp_pessoa" UNIQUE (id_pessoa)
);

CREATE INDEX idx_idp_subject ON pessoa_idp(idp_subject_id);
CREATE INDEX idx_pessoa_idp_pessoa ON pessoa_idp(id_pessoa);

-- ==========================================
-- 4. USUÁRIO (Gestão interna/contatos)
-- ==========================================
CREATE TABLE usuario (
    id UUID NOT NULL DEFAULT gen_random_uuid(),
    id_pessoa UUID NOT NULL,
    email VARCHAR(255) NOT NULL,
    ativo BOOLEAN DEFAULT TRUE,
    CONSTRAINT "PK_usuario" PRIMARY KEY (id),
    CONSTRAINT "FK_usuario_pessoa" FOREIGN KEY (id_pessoa) REFERENCES pessoa (id),
    CONSTRAINT "UQ_usuario_email" UNIQUE (email)
);

CREATE INDEX idx_usuario_pessoa ON usuario(id_pessoa);

-- ==========================================
-- 5. CANAL (Tabela separada para os tipos de canais)
-- ==========================================
CREATE TABLE canal (
    id UUID NOT NULL DEFAULT gen_random_uuid(),
    nome VARCHAR(50) NOT NULL UNIQUE,                   -- Ex: 'whitelabel', 'developer'
    descricao VARCHAR(100) NULL,                        -- Ex: 'Canal Portal WhiteLabel'
    ativo BOOLEAN DEFAULT TRUE,
    CONSTRAINT "PK_canal" PRIMARY KEY (id)
);

-- ==========================================
-- 6. PERFIL DE ACESSO (Catálogo de Perfis e Escopos vinculado ao Canal)
-- ==========================================
CREATE TABLE perfil (
    id UUID NOT NULL DEFAULT gen_random_uuid(),
    id_canal UUID NOT NULL,                             -- Referência à tabela canal
    nome VARCHAR(50) NOT NULL,                          -- Ex: 'Admin', 'Operador', 'Consumidor'
    descricao VARCHAR(100) NOT NULL,                    -- Ex: 'Administrador WhiteLabel'
    scope VARCHAR(150) NOT NULL UNIQUE,                 -- Ex: 'baas:portal-whitelabel:admin'
    ativo BOOLEAN DEFAULT TRUE,
    CONSTRAINT "PK_perfil" PRIMARY KEY (id),
    CONSTRAINT "FK_perfil_canal" FOREIGN KEY (id_canal) REFERENCES canal (id) ON DELETE CASCADE,
    CONSTRAINT "UQ_perfil_scope" UNIQUE (scope)
);

CREATE INDEX idx_perfil_canal ON perfil(id_canal);

-- ==========================================
-- 7. VÍNCULO DE PERFIL DO USUÁRIO (Atribuição)
-- ==========================================
CREATE TABLE usuario_perfil_acesso (
    id UUID NOT NULL DEFAULT gen_random_uuid(),
    id_usuario UUID NOT NULL,                           -- Vinculado ao usuário específico
    id_perfil UUID NOT NULL,                            -- Referência ao catálogo de perfis/escopos
    esta_bloqueado BOOLEAN DEFAULT FALSE,               -- Kill-switch local do acesso do usuário
    criado_em TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    atualizado_em TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,

    CONSTRAINT "PK_usuario_perfil_acesso" PRIMARY KEY (id),
    CONSTRAINT "FK_perfil_usuario" FOREIGN KEY (id_usuario) REFERENCES usuario (id) ON DELETE CASCADE,
    CONSTRAINT "FK_perfil_catalogo" FOREIGN KEY (id_perfil) REFERENCES perfil (id),
    CONSTRAINT "UQ_usuario_perfil" UNIQUE (id_usuario, id_perfil)
);

CREATE INDEX idx_usuario_perfil_usuario ON usuario_perfil_acesso(id_usuario);

-- ==========================================
-- 8. RELAÇÃO ENTRE PESSOAS (Hierarquia: Parceiro -> Cliente, Operador -> Cliente)
-- ==========================================
CREATE TABLE pessoa_relacionamento (
    id UUID NOT NULL DEFAULT gen_random_uuid(),
    id_origem UUID NOT NULL,   -- Ex: O Parceiro ou o Operador
    id_destino UUID NOT NULL,  -- Ex: O Cliente / Estabelecimento
    tipo VARCHAR(50) NOT NULL, -- Ex: 'PARCEIRO_CLIENTE', 'OPERADOR_CLIENTE'
    CONSTRAINT "PK_pessoa_relacionamento" PRIMARY KEY (id),
    CONSTRAINT "FK_relacionamento_origem" FOREIGN KEY (id_origem) REFERENCES pessoa (id),
    CONSTRAINT "FK_relacionamento_destino" FOREIGN KEY (id_destino) REFERENCES pessoa (id),
    CONSTRAINT "UQ_pessoa_relacionamento" UNIQUE (id_origem, id_destino, tipo)
);

-- ==========================================
-- 9. PRODUTOS DISPONÍVEIS NO SISTEMA
-- ==========================================
CREATE TABLE produto (
    id UUID NOT NULL DEFAULT gen_random_uuid(),
    nome VARCHAR(100) NOT NULL,
    descricao TEXT NULL,
    versao VARCHAR(20) NULL,
    ativo BOOLEAN DEFAULT TRUE,
    CONSTRAINT "PK_produto" PRIMARY KEY (id)
);

-- ==========================================
-- 10. CONFIGURAÇÕES DO TENANT POR PARCEIRO
-- ==========================================
CREATE TABLE tenant (
    id UUID NOT NULL DEFAULT gen_random_uuid(),
    id_pessoa UUID NOT NULL,              -- Referência à pessoa (o parceiro)
    tenant VARCHAR(100) NOT NULL,         -- Ex: 'cacawshow'
    tenant_alias VARCHAR(150) NOT NULL,   -- Ex: 'cacahow+id-parceiro'
    ativo BOOLEAN DEFAULT TRUE,
    CONSTRAINT "PK_tenant" PRIMARY KEY (id),
    CONSTRAINT "FK_tenant_pessoa" FOREIGN KEY (id_pessoa) REFERENCES pessoa (id),
    CONSTRAINT "UQ_tenant_pessoa" UNIQUE (id_pessoa),
    CONSTRAINT "UQ_tenant_nome" UNIQUE (tenant)
);

-- ==========================================
-- 11. PRODUTOS CONTRATADOS PELO PARCEIRO (Nome corrigido para produto_contratados)
-- ==========================================
CREATE TABLE produto_contratados (
    id UUID NOT NULL DEFAULT gen_random_uuid(),
    id_pessoa UUID NOT NULL,              -- Referência à pessoa (o parceiro)
    id_produto UUID NOT NULL,             -- Referência ao produto contratado
    ativo BOOLEAN DEFAULT TRUE,
    CONSTRAINT "PK_produto_contratados" PRIMARY KEY (id),
    CONSTRAINT "FK_produto_contratados_pessoa" FOREIGN KEY (id_pessoa) REFERENCES pessoa (id),
    CONSTRAINT "FK_produto_contratados_produto" FOREIGN KEY (id_produto) REFERENCES produto (id),
    CONSTRAINT "UQ_produto_contratados" UNIQUE (id_pessoa, id_produto)
);

Principais entidades

TabelaResponsabilidade
pessoaEntidade unificada para Parceiro, Cliente e Operador.
pessoa_idpCredenciais de IDP da pessoa (idp_subject_id, provedor), uma por pessoa.
usuarioUsuário de gestão/contato vinculado a uma pessoa (e-mail único).
canalCanais de acesso (ex.: whitelabel, developer).
perfilCatálogo de perfis e escopos (scope) vinculados a um canal.
usuario_perfil_acessoAtribuição de perfis ao usuário, com kill-switch (esta_bloqueado).
pessoa_relacionamentoHierarquia entre pessoas (PARCEIRO_CLIENTE, OPERADOR_CLIENTE).
produtoCatálogo de produtos/módulos disponíveis no sistema.
tenantConfiguração de tenant (Portais de Parceiros) por pessoa/parceiro.
produto_contratadosProdutos contratados/ativos por pessoa/parceiro.

4. Queries de apoio

Consultas usadas pela camada de regras de negócio. Os endpoints correspondentes estão documentados em Endpoints REST.

Produtos habilitados por parceiro

Lista os produtos contratados e ativos de um parceiro, base do endpoint de módulos por tenant. 

SELECT
    pes.nome AS parceiro,
    prod.nome AS produto_contratado,
    prod.versao,
    prod.descricao
FROM produto_contratados pp
JOIN pessoa pes ON pes.id = pp.id_pessoa
JOIN produto prod ON prod.id = pp.id_produto
WHERE pes.nome = 'EuFood' AND pp.ativo = TRUE;

Consulta de autorização (Token Exchange)

Executada pela policy do microsserviço durante o POST /v1/authorization/: a partir do idp_subject_id (claim sub) e do e-mail, resolve pessoa, usuário, tenant e agrega todos os scopes e canais do usuário em strings únicas. 

SELECT
    pes.id AS id_pessoa,
    pes.nome AS nome_pessoa,
    pes.cnpj,
    u.id AS id_usuario,
    u.email,
    u.ativo AS usuario_ativo,
    idp.idp_subject_id,
    idp.provedor,
    t.tenant,
    t.tenant_alias,
    -- Retorna todos os scopes concatenados em uma única string
    COALESCE(STRING_AGG(DISTINCT per.scope, ','), '') AS scopes,
    -- Retorna todos os canais distintos concatenados em uma única string (ex: "whitelabel developer")
    COALESCE(STRING_AGG(DISTINCT c.nome, ','), '') AS canais
FROM pessoa_idp idp
JOIN pessoa pes ON pes.id = idp.id_pessoa
JOIN usuario u ON u.id_pessoa = pes.id
LEFT JOIN tenant t ON t.id_pessoa = pes.id
LEFT JOIN usuario_perfil_acesso upa ON upa.id_usuario = u.id AND upa.esta_bloqueado = FALSE
LEFT JOIN perfil per ON per.id = upa.id_perfil
LEFT JOIN canal c ON c.id = per.id_canal
WHERE idp.idp_subject_id = 'sub-idp-admin-eufood-123'
  AND u.email = 'admin@eufood.com'
  AND u.ativo = TRUE
GROUP BY
    pes.id, pes.nome, pes.cnpj,
    u.id, u.email, u.ativo,
    idp.idp_subject_id, idp.provedor,
    t.tenant, t.tenant_alias;
