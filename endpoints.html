Endpoints REST

Endpoints da 1.0.0: identificação dinâmica de tenant, módulos contratados por tenant, Token Exchange via Axway API Gateway e os CRUDs transacionais de suporte. As respostas usam JSON.

Infraestrutura & Segurança

Esta seção detalha os endpoints de infraestrutura e segurança responsáveis pela identificação dinâmica de tenant e pelo processo de Token Exchange via Axway API Gateway para emissão do token final de aplicação.

Identificação de tenant

GET /tenant

Identifica o ambiente do parceiro/cliente com base na URL ou domínio solicitado, retornando as configurações de Portais de Parceiros.

AutenticaçãoPública (sem token)

Resposta (200 OK)

{
  "tenant_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
  "tenant_domain": "vivo.credito.bank.com.br",
  "idp": "idp.vivo.com.br",
  "whitelabel": {
    "tenant": "vivo",
    "logo": "https://asset.bank.com.br/vivo/logo.png"
  }
}

Módulos por tenant

GET /v1/tenant/{tenant}/modulos

Retorna os módulos/produtos contratados e ativos para o parceiro dono do tenant especificado (baseado na consulta de tenant e produto_contratados).

Parâmetros de path

NomeTipoDescrição
tenantstringSlug do tenant (ex.: cacawshow).

Consulta SQL subjacente

-- ==========================================
-- LISTAR PRODUTOS HABILITADOS POR PARCEIROS
-- ==========================================
SELECT
    pes.nome AS parceiro,
    prod.nome AS produto_contratado,
    prod.versao,
    prod.descricao
FROM produto_contratados pp
JOIN pessoa pes ON pes.id = pp.id_pessoa
JOIN produto prod ON prod.id = pp.id_produto
WHERE pes.nome = 'EuFood' AND pp.ativo = TRUE;

Autenticação e validação IDP (Token Exchange)

POST /v1/authorization/

Endpoint público exposto pelo Axway API Gateway. Recebe o token gerado pelo IDP externo e, com base na validação da identidade, emite o token definitivo da aplicação (o Token Exchange é executado pelo gateway).

Papel do microsserviço. A emissão do token é do Axway. O microsserviço expõe uma policy de validação que o gateway consulta para verificar se o IDP subject é válido e se o e-mail existe, retornando tenant, canais e escopos. Ver Adaptador de entrada (REST).
Content-Typeapplication/x-www-form-urlencoded

Corpo (x-www-form-urlencoded)

grant_type=urn:ietf:params:oauth:grant-type:token-exchange
subject_token=<JWT_DO_IDP>
subject_token_type=urn:ietf:params:oauth:token-type:access_token

Consulta de autorização (SQL)

-- ==========================================
-- CONSULTA PARA AUTORIZACAO
-- ==========================================
SELECT
    pes.id AS id_pessoa,
    pes.nome AS nome_pessoa,
    pes.cnpj,
    u.id AS id_usuario,
    u.email,
    u.ativo AS usuario_ativo,
    idp.idp_subject_id,
    idp.provedor,
    t.tenant,
    t.tenant_alias,
    -- Retorna todos os scopes concatenados em uma única string
    COALESCE(STRING_AGG(DISTINCT per.scope, ','), '') AS scopes,
    -- Retorna todos os canais distintos concatenados em uma única string (ex: "whitelabel developer")
    COALESCE(STRING_AGG(DISTINCT c.nome, ','), '') AS canais
FROM pessoa_idp idp
JOIN pessoa pes ON pes.id = idp.id_pessoa
JOIN usuario u ON u.id_pessoa = pes.id
LEFT JOIN tenant t ON t.id_pessoa = pes.id
LEFT JOIN usuario_perfil_acesso upa ON upa.id_usuario = u.id AND upa.esta_bloqueado = FALSE
LEFT JOIN perfil per ON per.id = upa.id_perfil
LEFT JOIN canal c ON c.id = per.id_canal
WHERE idp.idp_subject_id = 'sub-idp-admin-eufood-123'
  AND u.email = 'admin@eufood.com'
  AND u.ativo = TRUE
GROUP BY
    pes.id, pes.nome, pes.cnpj,
    u.id, u.email, u.ativo,
    idp.idp_subject_id, idp.provedor,
    t.tenant, t.tenant_alias;

CRUDs transacionais

Endpoints de gestão sobre o modelo relacional (esquema OLTP). Exclusão é lógica (ativo = FALSE) para preservar a integridade transacional.

Gerenciamento de pessoas e usuários

MétodoRotaDescrição
POST/v1/pessoasCadastra uma nova entidade (pessoa + usuário + regra de IDP opcional).
GET/v1/pessoas/{id}Retorna os dados cadastrais da pessoa e seu vínculo de usuário.
PUT/v1/pessoas/{id}Atualiza informações cadastrais ou altera o status ativo.
DELETE/v1/pessoas/{id}Exclusão lógica (ativo = FALSE), preservando a integridade transacional.

Gerenciamento de módulos (produtos)

MétodoRotaDescrição
GET/v1/produtosLista todos os produtos/módulos disponíveis no sistema (tabela produto).
POST/v1/parceiros/{id_parceiro}/produtosAssocia um novo produto contratado ao parceiro (produto_contratados).
