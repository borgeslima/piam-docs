Implementação — Spring Boot & Hexagonal

Como o processo de autorização de parceiro se traduz em código com Spring Boot e Spring Data JPA, seguindo a arquitetura hexagonal (Ports & Adapters). O foco é o caso de uso de validação de autorização sobre o modelo OLTP — a emissão do token (Token Exchange) fica a cargo do Axway API Gateway.

Conteúdo ilustrativo. Os trechos de código a seguir são exemplos de documentação para orientar a implementação. Não constituem um projeto compilável nem substituem revisão de segurança, tratamento de erros e testes.

Abordagem hexagonal

A arquitetura hexagonal isola o domínio e os casos de uso das tecnologias de entrega e persistência. O núcleo depende apenas de portas (interfaces); os adaptadores implementam essas portas para o mundo externo.

domain

Modelo e regras de negócio puras (sem Spring, sem JPA). Ex.: identidade do parceiro, agregação de scopes/canais, regra de bloqueio.

application

Casos de uso e as portas de entrada (use cases) e de saída (repositórios/serviços externos) que o domínio precisa.

adapters

in: controllers REST. out: repositórios Spring Data JPA, cliente do IDP. Traduzem entre o mundo externo e as portas.

Domínio

Modelo de resultado da autorização, sem dependências de framework:

package com.bank.piam.autorizacao.domain.model;

import java.util.List;

public record ResultadoAutorizacao(
        String idPessoa,
        String nomePessoa,
        String cnpj,
        String idUsuario,
        String email,
        String idpSubjectId,
        String provedor,
        String tenant,
        String tenantAlias,
        List<String> scopes,
        List<String> canais
) {
    public boolean possuiAcesso() {
        return scopes != null && !scopes.isEmpty();
    }
}

Portas (application)

Porta de entrada — o caso de uso exposto ao adaptador REST:

package com.bank.piam.autorizacao.application.port.in;

import com.bank.piam.autorizacao.domain.model.ResultadoAutorizacao;

public interface AutorizarParceiroUseCase {

    ResultadoAutorizacao autorizar(ComandoAutorizacao comando);

    record ComandoAutorizacao(String idpSubjectId, String email) {}
}

Porta de saída — o que o domínio precisa da persistência (sem citar JPA):

package com.bank.piam.autorizacao.application.port.out;

import com.bank.piam.autorizacao.domain.model.ResultadoAutorizacao;
import java.util.Optional;

public interface AutorizacaoRepositoryPort {

    Optional<ResultadoAutorizacao> buscarPorIdpSubjectEEmail(String idpSubjectId, String email);
}

Serviço de aplicação — orquestra a regra de negócio:

package com.bank.piam.autorizacao.application.service;

import com.bank.piam.autorizacao.application.port.in.AutorizarParceiroUseCase;
import com.bank.piam.autorizacao.application.port.out.AutorizacaoRepositoryPort;
import com.bank.piam.autorizacao.domain.exception.IdentidadeNaoEncontradaException;
import com.bank.piam.autorizacao.domain.model.ResultadoAutorizacao;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class AutorizarParceiroService implements AutorizarParceiroUseCase {

    private final AutorizacaoRepositoryPort repository;

    public AutorizarParceiroService(AutorizacaoRepositoryPort repository) {
        this.repository = repository;
    }

    @Override
    @Transactional(readOnly = true)
    public ResultadoAutorizacao autorizar(ComandoAutorizacao comando) {
        return repository
                .buscarPorIdpSubjectEEmail(comando.idpSubjectId(), comando.email())
                .filter(ResultadoAutorizacao::possuiAcesso)
                .orElseThrow(() -> new IdentidadeNaoEncontradaException(comando.idpSubjectId()));
    }
}

Consulta de autorização (agrega scopes e canais) e adaptador que implementa a porta:

package com.bank.piam.autorizacao.adapters.out.persistence.repository;

import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.Repository;
import org.springframework.data.repository.query.Param;
import java.util.Optional;

public interface AutorizacaoQueryRepository extends Repository<Object, Long> {

    // Projecao nativa espelhando a "Consulta de autorizacao" do OLTP.
    @Query(value = """
        SELECT pes.id AS id_pessoa, pes.nome AS nome_pessoa, pes.cnpj,
               u.id AS id_usuario, u.email, u.ativo AS usuario_ativo,
               idp.idp_subject_id, idp.provedor, t.tenant, t.tenant_alias,
               COALESCE(STRING_AGG(DISTINCT per.scope, ','), '') AS scopes,
               COALESCE(STRING_AGG(DISTINCT c.nome, ','), '')  AS canais
        FROM pessoa_idp idp
        JOIN pessoa pes ON pes.id = idp.id_pessoa
        JOIN usuario u ON u.id_pessoa = pes.id
        LEFT JOIN tenant t ON t.id_pessoa = pes.id
        LEFT JOIN usuario_perfil_acesso upa ON upa.id_usuario = u.id AND upa.esta_bloqueado = FALSE
        LEFT JOIN perfil per ON per.id = upa.id_perfil
        LEFT JOIN canal c ON c.id = per.id_canal
        WHERE idp.idp_subject_id = :sub AND u.email = :email AND u.ativo = TRUE
        GROUP BY pes.id, pes.nome, pes.cnpj, u.id, u.email, u.ativo,
                 idp.idp_subject_id, idp.provedor, t.tenant, t.tenant_alias
        """, nativeQuery = true)
    Optional<AutorizacaoView> buscar(@Param("sub") String sub, @Param("email") String email);
}
package com.bank.piam.autorizacao.adapters.out.persistence;

import com.bank.piam.autorizacao.application.port.out.AutorizacaoRepositoryPort;
import com.bank.piam.autorizacao.domain.model.ResultadoAutorizacao;
import org.springframework.stereotype.Component;
import java.util.Arrays;
import java.util.List;
import java.util.Optional;

@Component
public class AutorizacaoJpaAdapter implements AutorizacaoRepositoryPort {

    private final AutorizacaoQueryRepository repository;

    public AutorizacaoJpaAdapter(AutorizacaoQueryRepository repository) {
        this.repository = repository;
    }

    @Override
    public Optional<ResultadoAutorizacao> buscarPorIdpSubjectEEmail(String sub, String email) {
        return repository.buscar(sub, email).map(v -> new ResultadoAutorizacao(
                v.getIdPessoa(), v.getNomePessoa(), v.getCnpj(),
                v.getIdUsuario(), v.getEmail(), v.getIdpSubjectId(), v.getProvedor(),
                v.getTenant(), v.getTenantAlias(),
                split(v.getScopes()), split(v.getCanais())
        ));
    }

    private static List<String> split(String csv) {
        return (csv == null || csv.isBlank()) ? List.of() : Arrays.asList(csv.split(","));
    }
}

Adaptador de entrada (REST)

Responsabilidade. O Token Exchange (emissão do token de aplicação) é feito pelo Axway API Gateway, não pelo microsserviço. O endpoint /v1/authorization é uma policy de validação que o gateway consulta: ele apenas valida se o IDP subject é válido e se o e-mail existe, e devolve os dados de autorização (pessoa, tenant, canais e escopos). O microsserviço não decodifica o token do IDP nem emite token.

O controller recebe o idp_subject_id (claim sub) e o email — extraídos pelo gateway a partir do token do IDP já validado —, delega ao caso de uso e retorna o resultado da autorização: 

package com.bank.piam.autorizacao.adapters.in.rest;

import com.bank.piam.autorizacao.application.port.in.AutorizarParceiroUseCase;
import com.bank.piam.autorizacao.application.port.in.AutorizarParceiroUseCase.ComandoAutorizacao;
import com.bank.piam.autorizacao.domain.model.ResultadoAutorizacao;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/v1/authorization")
public class AutorizacaoController {

    private final AutorizarParceiroUseCase useCase;

    public AutorizacaoController(AutorizarParceiroUseCase useCase) {
        this.useCase = useCase;
    }

    // Chamado pela policy do Axway. Valida IDP subject + existencia do e-mail
    // e retorna os dados de autorizacao (nao emite token).
    @PostMapping("/validate")
    public AutorizacaoResponse validar(@RequestBody ValidarRequest req) {
        ResultadoAutorizacao r = useCase.autorizar(
                new ComandoAutorizacao(req.idpSubjectId(), req.email()));
        return AutorizacaoResponse.de(r);
    }

    public record ValidarRequest(String idpSubjectId, String email) {}

    public record AutorizacaoResponse(
            String idPessoa,
            String tenant,
            java.util.List<String> canais,
            java.util.List<String> scopes
    ) {
        static AutorizacaoResponse de(ResultadoAutorizacao r) {
            return new AutorizacaoResponse(r.idPessoa(), r.tenant(), r.canais(), r.scopes());
        }
    }
}

Se o IDP subject não existir, o e-mail não bater ou o acesso estiver bloqueado, o caso de uso lança exceção (mapeada para 401/403), e o gateway não prossegue com a emissão do token.
