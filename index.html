Estratégia de Autorização e Autenticação

Esta documentação define o fluxo de autenticação e autorização para aplicações parceiras (Portais de Parceiros / Multi-Tenant), combinando a identificação dinâmica de tenant, a federação de identidade via Provedor de Identidade (IDP) e a troca de tokens (Token Exchange) no Axway API Gateway para emissão do token final de aplicação com claims enriquecidas.

Visão geral

O microsserviço identifica o ambiente do parceiro/cliente (tenant), faz a ponte com o IDP externo através do IDP Subject (claim sub), valida a identidade contra o banco transacional e emite o token definitivo da aplicação. O controle de acesso é sustentado por um modelo relacional (OLTP) que unifica pessoas, usuários, relacionamentos, autorizações de IDP, tenants e produtos contratados.

Camadas da aplicação

A arquitetura é dividida em três camadas principais para garantir desacoplamento, segurança e facilidade de manutenção.

Persistência (Banco de Dados)

Mantém a integridade transacional de entidades unificadas (pessoa, usuario), credenciais de IDP (pessoa_idp), controle de acesso por canal/perfil (canal, perfil, usuario_perfil_acesso) e o ecossistema multi-tenant (tenant e produto_contratados).

Regras de Negócio e Serviços (API)

Processa a resolução de tenant, faz a ponte com o IDP através do IDP Subject (sub), valida status de bloqueio e gerencia os contratos de produtos por parceiro.

Exposição / Gateway (Axway)

Ponto de entrada que valida tokens JWT, intercepta chamadas públicas de tenant e orquestra o Token Exchange para as APIs protegidas.

Conceitos-chave

ConceitoDescrição
TenantAmbiente Portais de Parceiros de um parceiro, resolvido dinamicamente por domínio/URL.
IDP SubjectIdentificador único do usuário no provedor de identidade externo (claim sub), base para a validação.
Token ExchangeTroca do token do IDP externo pelo token definitivo da aplicação, orquestrada pelo Axway.
PerfilDeterminação de PARCEIRO ou OPERADOR a partir dos relacionamentos no banco.
Kill-switchBloqueio local do acesso via esta_bloqueado, independente do IDP externo.
